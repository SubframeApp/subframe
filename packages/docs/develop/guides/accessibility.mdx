Interactive primitives provide behavior such as keyboard navigation and focus management. Your interface still needs meaningful labels, appropriate semantics, visible focus states, and sufficient contrast.

## Labeling controls

Generated components pass extra props to their root element. For a compound component, put input attributes on the input subcomponent. `TextField` supplies the label and layout; `TextField.Input` is the form control:

```tsx EmailField.tsx
import { TextField } from "@/ui/components/TextField"

export function EmailField({ hasError = false }: { hasError?: boolean }) {
  return (
    <div>
      <TextField label="Email">
        <TextField.Input
          name="email"
          type="email"
          autoComplete="email"
          required
          aria-invalid={hasError}
          aria-describedby={hasError ? "email-error" : undefined}
        />
      </TextField>
      {hasError && <p id="email-error">Enter a valid email address.</p>}
    </div>
  )
}
```

Use unique IDs if you render more than one copy of this field. Give icon-only buttons an accessible name with `aria-label`. Prefer native semantics, such as a button for an action, before adding a `role` attribute.

## Checking the finished interface

Test keyboard navigation, focus order, control labels, and error messages in the running app. Check contrast and both light and dark modes. Accessible primitives alone do not make the full page accessible.

For reusable behavior, extend the component's [wrapper](/develop/concepts/syncing-components#wrapping-components).
