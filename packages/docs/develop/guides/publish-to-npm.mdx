Use a package when several apps need versioned releases of the same component library. Sync designs into the library repository, then let consuming apps install its releases.

## Preparing the package

1. Create a package with a `package.json` and a React TypeScript configuration.
2. [Initialize Subframe](/develop/installation) inside that package. Choose a dedicated sync directory and set the import alias to your package name, such as `@acme/ui/*`.
3. Sync the components, then configure a library build that emits JavaScript and TypeScript declarations. Preserve `"use client"` directives when supporting React Server Components.
4. Export the built components and layouts through their wrapper entry points. Include any generated icons, utilities, and theme files those exports need. The [monorepo guide](/develop/frameworks/monorepo#exporting-components-from-the-package) shows the source structure; a published build needs exports pointing to its emitted files.
5. Declare the runtime dependencies used by your components, including `@subframe/core`. Declare compatible React and React DOM peer dependencies.

Subframe generates source files. Your package's build and release workflow determines the published module formats, exports, and versions.

## Loading styles in consuming apps

Choose how consumers load the library's styles:

- **Consumers use Tailwind:** export the generated theme and tell each app how to load it and scan your package's component files. Tailwind does not scan `node_modules` automatically; v4 needs an explicit `@source`, while v3 needs a matching `content` path.
- **The package ships compiled CSS:** build the styles as part of your release, export the stylesheet, and tell consumers to import it.

Include instructions for any font files or other assets your library requires.

## Checking a release

Build the package, then use [npm pack](https://docs.npmjs.com/cli/v11/commands/npm-pack/) to create a local tarball. Install that tarball in a consuming app and verify component imports, types, styles, fonts, and interactive behavior before publishing through your normal release workflow.

For later updates, sync design changes into the library repository, rebuild, and publish a new version. Consuming apps receive the changes when they update the package.
