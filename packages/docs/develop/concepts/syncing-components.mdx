---
title: Syncing components
description: Pull component and theme changes from Subframe into your codebase.
---

After [installing Subframe](/develop/installation), run the CLI from your project root:

```bash
npx @subframe/cli@latest sync --all
```

To sync specific components and their dependencies:

```bash
npx @subframe/cli@latest sync Button Alert Accordion
```

The CLI uses `directory`, `importAlias`, and `cssType` from your local `.subframe/sync.json`. It writes generated components, layouts, theme files, and supporting files into that directory.

<Warning>
  A full sync replaces the managed directory's unprotected contents, including unrelated files you put there. Keep
  application code outside this directory, or add `@subframe/sync-disable` to each file you need to preserve.
</Warning>

Sync runs from Subframe to your codebase. It does not send local edits back to the design.

## Adding business logic

Generated components handle layout, styling, and built-in interactions. Your app supplies API calls, routing, and product state.

### Adding handlers and attributes

Props pass through to the component's root element. Use attributes appropriate for that element:

```tsx
import { Button } from "@/ui/components/Button"

export function SaveButton({ onSave }: { onSave: () => void }) {
  return <Button onClick={onSave}>Save changes</Button>
}
```

### Using slots to access nested props

Use a slot or subcomponent to reach an element inside a component. For example, form attributes belong on `TextField.Input`, while the surrounding `TextField` supplies the label and layout:

```tsx
import { TextField } from "@/ui/components/TextField"

export function EmailField() {
  return (
    <TextField label="Email">
      <TextField.Input name="email" type="email" autoComplete="email" required />
    </TextField>
  )
}
```

### Wrapping components

Each component has a generated source file and an `index.tsx` wrapper. Add reusable behavior in the wrapper and mark that file with `@subframe/sync-disable`.

This wrapper adds an optional `busy` state while preserving the button's props and ref:

```tsx src/ui/components/Button/index.tsx
"use client"
// @subframe/sync-disable
import { forwardRef } from "react"
import { Button as ButtonComponent, type ButtonRootProps } from "./Button"

export interface ButtonProps extends ButtonRootProps {
  busy?: boolean
}

export const Button = forwardRef<HTMLButtonElement, ButtonProps>(function Button(
  { busy = false, disabled, children, ...props },
  ref,
) {
  return (
    <ButtonComponent {...props} ref={ref} disabled={disabled || busy} aria-busy={busy}>
      {busy ? "Saving…" : children}
    </ButtonComponent>
  )
})
```

Set `busy` from the application while saving. The generated `Button.tsx` keeps receiving design updates; imports from `@/ui/components/Button` resolve to your wrapper.

See [Component directories](/develop/upgrading/component-directories) for the layout and migration steps.

### Disabling sync

Add this comment anywhere in a file to preserve it during sync:

```tsx
// @subframe/sync-disable
```

The marker applies to that file alone:

- **`index.tsx`:** protects your wrapper while the generated component keeps syncing.
- **`Button.tsx`:** protects direct edits to the generated source, but stops that file receiving design updates.

To resume syncing a file, remove the marker. The next sync replaces it with Subframe's generated version.
