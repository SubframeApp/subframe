This guide covers the workflow for a component library managed in Subframe. Components sync through the CLI, while pages are implemented in your app with an agent or copied from the **Code** tab. Add application logic such as API calls, routing, and product-specific state in your codebase.

If you already have an app and want to edit it using your existing components, start with the [quickstart](/quickstart).

#### Components vs pages

As a developer, you should treat **components** and **pages** differently:

- **Components** are your design system (e.g. buttons, inputs, cards). They are [synced via CLI](/develop/concepts/syncing-components) to a folder in your codebase (default: `./ui/components`). Each component syncs as a directory — a source file that Subframe generates and you don't modify, plus a wrapper `index.tsx` that you can extend (see [Component directories](/develop/upgrading/component-directories)).
- **Pages** are screens built from components. Implement them with [Agent chat](/design/code-mode/overview#implementing-a-page-with-agent-chat), an external agent using MCP, or [copied React code](/design/code-mode/overview#inspecting-page-code). Page code is meant to be modified in your app.

In a nutshell, **components are synced, pages are exported**. This is because pages are typically modified with business logic like API calls after export. If your component needs logic after syncing, see our guide on best practices for [exporting components](/develop/concepts/syncing-components).

### Syncing components

When the designs are ready for handoff, sync the `Button` and `SocialSignInButton` code to your codebase by running the following command:

<CodeGroup>

```bash npm
npx @subframe/cli@latest sync Button SocialSignInButton
```

```bash yarn
yarn dlx @subframe/cli@latest sync Button SocialSignInButton
```

```bash pnpm
pnpx @subframe/cli@latest sync Button SocialSignInButton
```

```bash bun
bunx @subframe/cli@latest sync Button SocialSignInButton
```

</CodeGroup>

You can also sync all design system components at once:

<CliSyncAllCommand />

The CLI sync command pulls `Button`, `SocialSignInButton`, and any other components into a specific folder in your codebase. By default this folder is located in the `./src/ui/components` folder but can be configured in the [project settings](/design/projects/project-settings).

```
src/ui/
└─ components/
// [!code ++:6]
  ├─ Button/
  │  ├─ Button.tsx
  │  └─ index.tsx
  └─ SocialSignInButton/
     ├─ SocialSignInButton.tsx
     └─ index.tsx
```

Each component syncs as a directory: the source file Subframe generates (`Button.tsx`) plus a wrapper `index.tsx` that re-exports it and is the import entrypoint. See [Component directories](/develop/upgrading/component-directories) for why, and how to add your own logic in the wrapper.

### Exporting pages

Subframe generates page code with stubs for business logic that need to be filled in:

You can implement the page in three ways:

- **Agent chat** - in the desktop app, [connect your codebase](/agent/connecting-your-codebase) and ask the agent to implement the page.
- **MCP server** - connect an external AI tool to Subframe and ask it to integrate the page code using the [page link](/agent/mcp-server#using-the-mcp-server).
- **Copy/paste** - Open the **Code** tab in Subframe and copy the React code.

## Iterating on designs

After the initial export, both designs and code will evolve. Here's how to handle changes:

### Designer makes changes

Subframe lets designers own the visual layer. Apply design changes to your codebase by syncing components or updating the page implementation.

**Component updates**

Run the sync command to get the latest component code:

<CliSyncAllCommand />

If a component has breaking changes, TypeScript will throw errors wherever that component is used. This makes it easy for developers to find and update the affected code.

**Page updates**

Ask Agent chat or an external agent connected through MCP to update the page code:

```text
Update the existing page to match the Subframe design at
https://app.subframe.com/<YOUR_PROJECT_ID>/design/<DESIGN_ID>/edit.

Preserve all existing functionality unless the new design requires a change.
```

The agent uses the latest design and your existing code to make the update. Review the changes to confirm the page still behaves as intended.

### Developer makes changes

Often times, you will need to add or modify the component behavior after handoff.

The best practice is to add your logic to the component's [wrapper `index.tsx`](/develop/concepts/syncing-components#wrapping-components). You probably don't need to sync code back to Subframe, since the source file that Subframe generates stays untouched and keeps receiving design updates. As a last resort, you can [disable sync](/develop/concepts/syncing-components#disabling-sync) for the source file itself.

CLI sync runs from Subframe to your codebase. To bring your running app back onto the canvas, [capture a page or element](/browser/capturing-as-designs) in the desktop browser. The capture creates an editable design from the rendered page; it does not sync your source code back to Subframe.

## Beyond handoff

Once a feature ships, page designs may drift from code. That's okay — page designs are artifacts for communication. Once the feature is live, the code is the source of truth.

Components are different. They stay synced, so Subframe remains the single source of truth for your design system. When a designer updates a button or input, you re-run sync and every page using that component gets the update.
