This workflow applies when you manage your component library in Subframe. Sync the reusable components, then implement pages and application logic in your codebase. For an existing app with its own component library, use the [desktop workflow](/quickstart).

## Separating components and pages

As a developer, you should treat **components** and **pages** differently:

- **Components** are your design system (e.g. buttons, inputs, cards). They are [synced via CLI](/develop/concepts/syncing-components) to a folder in your codebase inside the directory chosen during setup. Each component syncs as a directory — a source file that Subframe generates and you don't modify, plus a wrapper `index.tsx` that you can extend (see [Component directories](/develop/upgrading/component-directories)).
- **Pages** are screens built from components. They are [exported](/design/code-mode/overview#inspecting-page-code) as copyable React code or using the MCP server and are meant to be modified after export.

Keep page logic in your app and reusable component logic in [sync-protected wrappers](/develop/concepts/syncing-components#wrapping-components).

### Syncing components

When the designs are ready for handoff, sync the `Button` and `SocialSignInButton` code to your codebase by running the following command:

<CodeGroup>

```bash npm
npx @subframe/cli@latest sync Button SocialSignInButton
```

```bash yarn
yarn dlx @subframe/cli@latest sync Button SocialSignInButton
```

```bash pnpm
pnpx @subframe/cli@latest sync Button SocialSignInButton
```

```bash bun
bunx @subframe/cli@latest sync Button SocialSignInButton
```

</CodeGroup>

You can also sync all design system components at once:

<CliSyncAllCommand />

The CLI writes components under the `directory` recorded in your local `.subframe/sync.json`. For a sync directory of `./src/ui`, these files are created:

```text
src/ui/
└─ components/
// [!code ++:6]
  ├─ Button/
  │  ├─ Button.tsx
  │  └─ index.tsx
  └─ SocialSignInButton/
     ├─ SocialSignInButton.tsx
     └─ index.tsx
```

Each component syncs as a directory: the source file Subframe generates (`Button.tsx`) plus a wrapper `index.tsx` that re-exports it and is the import entrypoint. See [Component directories](/develop/upgrading/component-directories) for why, and how to add your own logic in the wrapper.

## Iterating on designs

After the initial export, both designs and code will evolve. Here's how to handle changes:

### Designer makes changes

Subframe lets designers own the visual layer. After a design changes, sync its components or ask your agent to update the implemented page.

**Component updates**

Run the sync command to get the latest component code:

<CliSyncAllCommand />

If a component has breaking changes, TypeScript will throw errors wherever that component is used. This makes it easy for developers to find and update the affected code.

**Page updates**

The recommended way is to prompt your AI tool using the MCP server to update the page code:

```text
Update the existing page to match the Subframe design at
https://app.subframe.com/<YOUR_PROJECT_ID>/design/<DESIGN_ID>/edit.

Preserve all existing functionality unless the new design requires a change.
```

The agent can read the latest design and update the implementation. Review its diff and test existing behavior before accepting the change.

### Developer makes changes

Often times, you will need to add or modify the component behavior after handoff.

The best practice is to add your logic to the component's [wrapper `index.tsx`](/develop/concepts/syncing-components#wrapping-components). You probably don't need to sync code back to Subframe, since the source file that Subframe generates stays untouched and keeps receiving design updates. As a last resort, you can [disable sync](/develop/concepts/syncing-components#disabling-sync) for the source file itself.

To bring the current app back into your design workflow, [capture its rendered page](/browser/capturing-as-designs) or ask the agent to [recreate a component from your codebase](/design/components/importing). These create editable design data; they do not preserve arbitrary application logic.

## Beyond handoff

Once a feature ships, page designs may drift from code. That's okay — page designs are artifacts for communication. Once the feature is live, the code is the source of truth.

Components are different. They stay synced, so Subframe remains the single source of truth for your design system. When a designer updates a button or input, you re-run sync and every page using that component gets the update.
